# Study-03 — 3단계 구현 프롬프트

PRD.md의 요구사항을 아래 순서로 구현한다. 기존 단계의 코드를 이어서 수정하며, 단계가 끝나면 실제 확인 결과와 남은 작업을 기록한다. 이 문서는 앞으로 사용할 프롬프트이며, 실행을 마친 작업 기록이 아니다.

## 1단계 — 퀴즈의 기본 흐름

```text
Study-03의 PRD.md, AGENTS.md, questions.json과 QUESTIONS.md를 읽고 기본 퀴즈 게임을 구현해 줘.

요구사항:
- 한국사·과학·지리·일반상식·컴퓨터공학 순서로 각각 10문제, 총 50문제를 출제한다.
- questions.json을 원본으로 사용하며, answer_index는 0부터 시작한다. 질문·보기·정답·해설·출처를 임의로 바꾸거나 미확인 문제를 추가하지 않는다.
- index.html을 브라우저에서 직접 열어 실행할 수 있는 일반 HTML·CSS·JavaScript로 만든다. 서버, 프레임워크, API 키와 새 의존성은 필요 없다.
- 파일 직접 열기에서는 로컬 JSON을 fetch하는 방식이 제한될 수 있으므로, 원본 JSON에서 실행용 데이터를 생성해 포함한다. 수동으로 별도 문제은행을 작성하지 않는다. 원본과 실행 데이터의 일치 여부를 확인한다.
- 시작 화면에서 5개 분야, 50문제, 정답당 1점과 50점 만점을 안내한다.
- 문제 화면에 분야, 전체 진행 상황, 질문과 4개 보기를 표시한다.
- 답을 고르면 한 번만 채점하고 보기 선택을 잠근다. 정답·오답, 올바른 정답, 해설, 출처 기관·제목·링크를 즉시 표시한다.
- 답변 전에는 다음 문제로 진행하지 못한다. 피드백을 읽은 뒤 사용자가 다음 문제 버튼을 누른다.
- 마지막 문제 뒤 총점과 분야별 점수를 표시한다. 다시 도전하면 이번 게임의 답변과 점수를 초기화한다.
- 정답·오답을 색상과 글자로 함께 표시하고, 기본 버튼과 키보드 조작을 지원한다. 사용자 입력이나 문제 내용을 HTML로 해석하지 않는다.

완료 확인:
- 모두 정답일 때 50점, 모두 오답일 때 0점이며 분야별 점수 합계가 총점과 같은지 확인한다.
- 반복 선택 시 중복 채점이 없는지, 10·20·30·40번째 문제 뒤 분야가 전환되는지 확인한다.
- 마지막 결과와 다시 도전의 초기화가 동작하는지 확인한다.
- 실제 실행하지 않은 검사를 성공한 것처럼 쓰지 않는다. 순위 저장과 화면 다듬기는 2단계에서 이어간다.
```

## 2단계 — 기록 저장과 화면 완성

```text
PRD.md와 AGENTS.md를 읽고 1단계의 게임을 이어서 완성해 줘. 기존 문제와 출처를 유지한다.

요구사항:
- 완료 화면에서 이름을 입력하고 이번 결과를 저장할 수 있게 한다. 이름은 앞뒤 공백을 제거한 1~20자이며 기록 저장 시에만 요구한다.
- 이름, 총점, 분야별 점수와 완료 시각을 현재 브라우저의 localStorage에 저장한다. 한 번의 완료 결과는 한 번만 저장한다.
- 높은 점수가 우선이다. 동점은 공동 순위로 표시하며 동점 기록의 표시 순서는 완료 시각이 빠른 순서다. 예: 50, 50, 40점은 1, 1, 3위다.
- 순위는 이 브라우저에 저장된 기록만을 대상으로 한다고 안내한다. 다른 컴퓨터와 동기화되는 온라인 순위로 표현하지 않는다.
- 새로고침 뒤 기록을 복원한다. 복원할 때 구조·이름·점수 범위·분야별 합계·시각을 검사한다.
- 저장 공간 접근 실패, 용량 부족, 손상된 기록이 있어도 게임을 플레이할 수 있게 한다. 실패 이유와 저장 여부를 안내하고, 손상된 기록을 자동으로 덮어쓰거나 삭제하지 않는다.
- 이름과 기록은 textContent 등으로 안전하게 표시한다. 외부 출처 링크는 HTTPS 주소를 확인하고 새 창 링크에는 적절한 rel 속성을 사용한다.
- 모바일과 데스크톱에서 보기·해설·출처·결과·순위가 읽히도록 화면을 다듬는다.
- 버튼에 명확한 이름, 키보드 초점 표시와 충분한 대비를 제공한다. 답변 결과를 보조기술에서 인지할 수 있게 하고 화면 전환 뒤 초점을 적절히 옮긴다.
- 브라우저 데이터를 지우면 기록이 사라질 수 있음을 안내한다. 서버, 계정, 타이머와 실시간 AI 출제는 추가하지 않는다.

완료 확인:
- 정상 저장·새로고침 복원·동점 순위·같은 결과의 중복 저장 방지를 확인한다.
- 빈 이름, 20자 초과 이름, HTML처럼 생긴 이름을 확인한다.
- 저장 차단, 잘못된 JSON, 잘못된 점수와 시각의 기존 데이터에서 게임이 동작하고 기존 기록이 보존되는지 확인한다.
- 모바일 너비와 키보드만으로 시작·답변·다음 문제·저장·다시 도전을 수행한다.
- 확인한 브라우저와 실제 결과를 기록한다. 이 단계에서도 문제 출처 검증을 기능 테스트와 혼동하지 않는다.
```

## 3단계 — 재검토와 제출 문서

```text
PRD.md의 완료 기준, AGENTS.md의 검증 규칙, questions.json, QUESTIONS.md와 구현 파일을 읽고 최종 점검해 줘.

작업:
- 5개 분야에 각각 10문제가 있고 컴퓨터공학 5개 세부 영역에 각각 2문제가 있는지 확인한다.
- 문제 ID와 질문의 중복, 보기 4개의 중복, 정답 인덱스, 해설과 출처 정보, 원본 JSON과 실행 데이터의 일치 여부를 확인한다.
- 출처의 해당 내용을 다시 읽어 정답과 해설을 점검한다. 접근 실패를 검증 성공으로 기록하지 않는다. 기존 FIDE 출처는 공식 검색 응답으로 확인한 상태라는 제한을 유지하거나, 본문을 재확인한 실제 결과로 갱신한다.
- 정답이 하나인지, 최상급의 기준·시점·범위·언어·알고리즘 전제가 명확한지 검토한다. 의심스러운 내용은 독립된 출처 2개 이상으로 대조하고 해결되지 않으면 교체한다.
- 문제를 수정하면 questions.json, 실행 데이터와 QUESTIONS.md를 함께 맞추고 문제 ID별 변경 이유·근거·확인일을 기록한다.
- 데이터 구조·채점·순위·저장 데이터 검사를 대상으로 작고 실행 가능한 검증 파일 하나를 남긴다. 설치된 런타임과 표준 기능을 사용한다.
- 1·2단계의 주요 사용자 흐름과 저장 오류 처리를 브라우저에서 확인하고 실제 결과를 기록한다.
- README.md에 과제 목적, 40→50문제 확장, 실행 방법, 분야와 채점, 브라우저 순위 범위, 제작 과정, 출처 검토 범위, 테스트 명령·실제 결과·남은 제한을 정리한다.
- Claude의 /memory나 /clear를 사용한 것처럼 기록하지 않는다. 새로운 대화에서 규칙을 읽고 재검토했다면 실제 수행한 경우에만 그렇게 적는다.
- Study-01·02의 문서 형식을 참고할 수 있으나 실행·제작 이력을 가져오지 않는다. 이 단계의 로컬 작업만으로 GitHub 업로드가 끝났다고 쓰지 않는다.

완료 보고:
- 수정한 파일, 실행한 검사와 결과, 미확인 항목을 짧게 설명한다.
- PRD의 완료 기준을 항목별로 대조해 미완료 기능이나 확인하지 않은 동작을 명시한다.
```
