# Study-03 — 출처를 확인하는 상식 퀴즈 게임

## 목적과 과제 근거

「07. 인공지능활용실습_할루시네이션 없는 AI 콘텐츠 만들기」를 바탕으로 4지선다 퀴즈 게임을 제작한다. AI가 생성한 문제를 신뢰할 수 있는 자료와 대조하고, 모호한 질문과 잘못된 정답을 수정하는 과정까지 기록한다. 오류가 전혀 없음을 보장하는 대신 확인 근거와 남은 한계를 공개한다.

PDF 5쪽은 한국사·과학·지리·일반상식 각 10문제, 총 40문제를 제시한다. 사용자와 합의해 컴퓨터공학 10문제를 추가한 총 50문제로 확장한다. PDF 3쪽의 ‘예술과 문화’는 일반상식 분야의 일부로 반영한다. 공식 제출 기한과 제출 형식은 자료에서 확인되지 않았다.

## 분야와 문제 구성

| 분야 | 문제 수 | 범위 |
|---|---:|---|
| 한국사 | 10 | 시대, 주요 사건, 인물, 제도와 문화유산 |
| 과학 | 10 | 물리, 화학, 생명과학, 지구과학 기초 |
| 지리 | 10 | 국가, 대륙, 지형과 지리적 위치 |
| 일반상식 | 10 | 문학, 예술, 문화와 생활 상식; 다른 분야와 중복 방지 |
| 컴퓨터공학 | 10 | 프로그래밍, 알고리즘, 자료구조, 운영체제, 네트워크 각 2문제 |

모든 문제는 보기 4개와 정답 1개를 가진다. 난이도는 기초 상식과 컴퓨터공학 입문 수준으로 한다. 논쟁적인 최상급, 변동이 잦은 순위, 기준 없는 성능 비교는 피한다. 조건이 필요한 문제는 질문 안에 시점·범위·측정 기준을 명시한다.

## 사용자 흐름

1. 시작 화면에서 분야, 총 문제 수, 채점 방식을 확인하고 게임을 시작한다.
2. 한국사 → 과학 → 지리 → 일반상식 → 컴퓨터공학 순서로 50문제를 푼다. 각 분야 안에서도 고정 순서를 사용한다.
3. 현재 분야와 전체 진행 상황을 표시한다. 답을 고르면 즉시 정답·오답, 올바른 정답, 해설과 출처 링크를 보여준다.
4. 답 선택 후 해당 문제의 선택을 잠그고 ‘다음 문제’ 버튼으로 진행한다. 중복 클릭으로 점수가 추가되지 않는다.
5. 마지막 문제 이후 총점, 분야별 점수와 순위를 표시한다. 사용자가 기록 저장을 선택하면 이름과 점수를 현재 브라우저에 저장한다.
6. 다시 도전하면 점수와 답변을 초기화하고 첫 문제부터 시작한다. 이미 저장된 순위 기록은 유지한다.

## 점수와 순위

- 정답당 1점, 오답은 0점, 총 50점 만점이다. 시간 제한과 속도 가산점은 없다.
- 순위는 현재 브라우저의 완료 기록을 대상으로 한다. 여러 사용자나 기기의 온라인 순위가 아니다.
- 높은 점수가 우선이며 같은 점수는 공동 순위로 표시한다. 동점 기록의 표시 순서는 완료 시각이 빠른 순서로 한다.
- 이름은 앞뒤 공백을 제거한 1~20자이며 HTML로 해석하지 않는다. 이름은 기록 저장 시에만 필요하다.
- 한 번의 완료 결과는 한 번만 저장한다. 저장 데이터는 이름, 총점, 분야별 점수와 완료 시각으로 제한한다.
- 브라우저 데이터를 삭제하면 기록도 사라질 수 있음을 안내한다. 저장 차단·용량 부족·잘못된 저장 데이터가 있어도 게임은 실행되며 기록 저장 상태를 안내한다.

## 문제의 근거와 검증

각 문제에 고유 ID, 분야, 질문, 보기 4개, 정답, 해설, 출처 제목·기관·URL, 확인 날짜를 기록한다. 가능하면 해당 사실을 직접 설명하는 공식 기관이나 원문 문서에 연결한다. 링크가 존재한다는 사실만으로 정답 검증을 완료했다고 판단하지 않는다.

- 문제와 정답이 출처의 설명과 일치하는지 확인한다.
- 보기 중 다른 정답이 가능한지 검토한다. 질문과 보기의 중복·모호한 표현을 제거한다.
- 의심스럽거나 해석이 갈리는 정보는 독립된 출처 2개 이상으로 교차 검증한다. 해결되지 않으면 문제를 교체한다.
- ‘가장 큰’, ‘최초’ 등의 표현에는 기준을 명시한다. 시간·지리·분류 범위를 필요한 만큼 한정한다.
- 컴퓨터공학 문제의 언어·프로토콜·구현별 차이는 질문에 조건을 적는다. 예를 들어 이진 탐색의 정렬 조건이나 자료구조의 동작 전제를 생략하지 않는다.
- 해설은 정답의 이유를 짧게 설명하고, 출처가 뒷받침하지 않는 추가 주장을 넣지 않는다.
- 검증 전후 변경 사항은 질문, 수정 내용, 수정 이유와 근거로 기록한다. 실제 발견한 사례만 기록하며 오류나 검증 이력을 꾸며내지 않는다.

## 실행과 접근성

Study-02의 정적 HTML·CSS·JavaScript 실행 방식을 따른다. 설치, 로그인, API 키 없이 index.html을 브라우저에서 열어 플레이한다. 문제는 미리 검증해 포함하며 실행 중 AI가 생성하지 않는다. 출처 사이트를 방문할 때는 인터넷 연결이 필요하다.

휴대전화와 데스크톱에서 읽고 조작할 수 있도록 구성한다. 보기와 진행 버튼은 키보드로 사용할 수 있고, 정답·오답은 색상과 함께 글자로 표시한다. 답변 결과는 보조기술에서도 인지할 수 있어야 한다.

## 제작 문서와 단계

| 파일 | 역할 |
|---|---|
| PRD.md | 합의한 요구사항과 완료 기준 |
| PROMPTS.md | 아래 3단계의 구현 프롬프트 |
| AGENTS.md | 프로젝트 작업 규칙과 문제 검증 기준 |
| README.md | 실행 방법, 과제 확장 사항, 실제 제작·검증 결과와 제한 사항 |
| 문제·출처 및 검증 기록 | 50문제의 근거와 실제 수정 이력 |
| index.html 및 필요한 CSS·JavaScript | 게임 실행 파일 |

1. 기본 흐름: 문제 데이터와 출처를 준비하고 시작·답변·피드백·진행·결과를 구현한다.
2. 기록과 화면: 분야별 결과, 브라우저 순위 저장, 반응형 화면과 접근성을 구현한다.
3. 검증과 제출 정리: 50문제를 재검토하고 기능을 확인한 뒤 실제 결과를 README와 검증 기록에 남긴다.

PDF의 Claude 명령어를 Codex에서 실행한 것처럼 기록하지 않는다. 검증 기준은 AGENTS.md에 남기고, 새 대화에서 해당 파일과 문제 파일을 읽어 재점검할 수 있도록 한다. Claude 사용이 공식 필수 조건인지 여부는 별도 제출 공지로 확인해야 한다.

## 완료 기준

- 분야별 10문제, 총 50문제이며 모든 문제의 보기·정답·해설·출처가 완비되어 있다.
- 실제 출처를 읽어 정답 근거를 확인하고, 미확인 문제는 완료 목록에 포함하지 않는다.
- 모두 정답이면 50점, 모두 오답이면 0점이며 분야별 점수 합계가 총점과 같다.
- 한 문제에서 반복 선택해도 한 번만 채점되고, 답변 전에는 다음 문제로 진행할 수 없다.
- 피드백, 마지막 결과, 다시 도전과 같은 결과의 중복 저장 방지가 정상 동작한다.
- 새로고침 뒤 순위가 복원되며 동점은 공동 순위로 표시한다.
- 저장 실패·손상된 저장 데이터가 있어도 게임을 플레이할 수 있다.
- 모바일 너비와 키보드 조작에서 주요 기능을 사용할 수 있다.
- 자동 검증 가능한 문제 구조·채점·순위 로직에는 작은 실행 가능한 검증을 남긴다. 브라우저 동작과 출처 확인 결과는 별도로 기록한다.
- 제작 과정과 테스트 결과는 실제 수행한 내용만 적는다.

## 이번 범위에서 제외

온라인 계정, 서버 순위, 기기 간 동기화, 시간 제한, 실시간 AI 출제, 별도 관리자 화면은 추가하지 않는다.
