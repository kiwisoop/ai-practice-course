# 체류 시간 늘리기

- **작성 방식:** 일반 방식 (Sequential Thinking MCP 미사용, 단일 응답 구상)
- **주제:** 웹 포트폴리오 방문자의 평균 체류 시간을 현재의 2배로 늘리는 전략
- **작성일:** 2026-11-17 (한국 시간)

## 1. 목표

웹 포트폴리오를 방문한 채용 담당자·동료 개발자·잠재 클라이언트가 첫 화면만 보고 이탈하지 않고, 프로젝트 상세 내용과 작업 과정을 탐색하도록 유도해 **평균 체류 시간을 현재 대비 2배**로 늘린다.

## 2. 주요 전략 5가지

### ① 첫 화면(Hero) 요약 및 대표 프로젝트 전면 배치
- 방문자가 5초 안에 직무 역량과 대표 결과물을 파악할 수 있도록 상단에 핵심 소개 한 줄과 대표 프로젝트 3개를 바로 배치한다.
- 추상적인 인사말 대신 해결한 문제와 기술 스택 태그를 명확히 보여준다.

### ② 결과물 나열에서 ‘문제-해결-성과’ 케이스 스터디로 전환
- 단순 스크린샷과 GitHub 링크만 두지 않고, **왜 만들었는지 → 어떤 기술적 난관이 있었는지 → 어떻게 해결했는지 → 무엇을 배웠는지**를 이야기 구조로 작성한다.
- 코드 일부나 아키텍처 다이어그램을 함께 배치해 읽을거리를 제공한다.

### ③ 브라우저에서 바로 조작해 보는 인터랙티브 요소 추가
- 정적 이미지 대신 직접 클릭해 볼 수 있는 미니 데모, 전후(Before/After) 비교 탭, 다크/라이트 화면 전환, 필터링 기능을 넣는다.
- 방문자가 직접 버튼을 눌러보게 만들면 자연스럽게 머무는 시간이 늘어난다.

### ④ 읽기 편한 가독성과 탐색 동선(내부 링크) 정리
- 긴 글은 목차(Table of Contents)와 예상 읽기 시간(예: 3분 소요)을 표시해 부담을 줄인다.
- 프로젝트 글 하단에 “비슷한 문제 해결 사례: 다음 프로젝트 보기” 버튼을 두어 한 페이지에서 끝나지 않고 연속 탐색을 유도한다.

### ⑤ 로딩 속도 및 모바일 화면 최적화
- 이미지 용량을 줄이고 모바일에서도 글자 크기와 여백이 깨지지 않게 정리해 불편함으로 인한 조기 이탈을 막는다.

## 3. 실행 우선순위

1. **즉시 적용 (1주 내):** 첫 화면 문구 정리, 대표 프로젝트 3개 선정, 프로젝트 하단 ‘다음 프로젝트’ 이동 링크 추가
2. **단기 적용 (2~3주):** 대표 프로젝트 3개의 상세 케이스 스터디 작성 및 목차 추가
3. **중기 적용 (1개월):** 브라우저 내 미니 데모 또는 전후 비교 인터랙션 추가

## 4. 측정 지표 (KPI)

- **평균 세션 체류 시간 (Average Session Duration):** 개편 전 대비 2배 증가 여부
- **이탈률 (Bounce Rate):** 첫 페이지만 보고 나가는 비율 감소 여부
- **페이지뷰/세션 (Pages per Session):** 방문자당 조회한 프로젝트 페이지 수
- **스크롤 깊이 (Scroll Depth):** 상세 페이지의 50%·75% 이상 읽은 비율
