## 1. Sequential Thinking MCP 6단계 추론 요약

| 단계 | 추론 구분 | 핵심 내용 |
| --- | --- | --- |
| **Step 1** | 문제 정의·지표 분해 | 평균 체류 시간 2배 달성을 ① 첫 10초 내 이탈률 감소, ② 케이스 스터디 탐색 깊이 증가, ③ 인터랙티브 데모 조작 시간 확보의 3개 축으로 분해 |

| **Step 5** | 주 지표 및 역효과 방지(Guardrail) 지표 설정 | 체류 시간만 늘고 채용·연락 전환이 떨어지는 왜곡을 막기 위해 주 지표(평균 체류 시간, 참여 세션 비율)와 가드레일 지표(LCP 2.5초 이내, GitHub/연락 클릭률 유지)를 분리 |

## 2. 목표 분해와 근거 (왜 체류 시간이 짧은가?)

포트폴리오 평균 체류 시간($T_{avg}$)은 크게 **조기 이탈 비율($r_{bounce}$)**과 **잔류 방문자의 탐색 시간($T_{engaged}$)**으로 결정됩니다.

$$T_{avg} = r_{bounce} \times T_{bounce} + (1 - r_{bounce}) \times T_{engaged}$$

- **현재 문제:** 첫 화면에서 어떤 문제를 푸는 개발자인지 10초 안에 보이지 않거나 외부 데모 링크가 열리지 않으면 $r_{bounce}$가 높아지고, 프로젝트 설명이 단순 기능 나열이면 $T_{engaged}$가 30~40초에 머뭅니다.
- **핵심 근거:** 글자 수만 늘리면 빠르게 훑어보는 채용 담당자의 조기 이탈률($r_{bounce}$)이 오히려 높아질 수 있습니다. 따라서 **상단 요약으로 조기 이탈을 줄이고, 중간의 경량 실행 데모와 의사결정 근거(대안 비교)로 잔류 탐색 시간을 늘려야** 전체 평균 체류 시간이 안정적으로 2배에 도달합니다.

## 3. 가설 수정으로 도출한 핵심 구현 전략

### ① 10초 요약 카드(TL;DR) + 심층 아키텍처 접기/펼치기 구조
- 각 프로젝트 상단에 **[문제 정의 / 선택한 해결책 / 검증된 결과 / 내 기여도]** 4줄 요약을 고정 배치합니다.
- 아래에는 **“왜 A 대신 B 방식을 선택했는가(트레이드오프)”**와 **“실패했던 시도와 수정 과정”**을 배치해 기술 검토자의 심층 열람을 유도합니다.

### ② 외부 이동 없는 ‘인라인 경량 데모(Inline Micro-Demo)’ 내장
- 별도 서버나 API 키 입력이 필요한 무거운 앱은 방문자가 실행해 보지 않고 닫을 가능성이 높습니다.
- 포트폴리오 페이지 안에서 **모의 데이터(Mock Data)나 로컬 스토리지로 즉시 동작하는 핵심 기능 위젯**(예: 쇼핑 리스트 추가/체크 체험, 분류 규칙 테스트, 전후 UI 비교 탭)을 바로 조작할 수 있게 제공합니다. (예상 추가 체류 시간: +45~90초)

### ③ 문제 유형 기반의 ‘연속 탐색 동선’ 설계
- 페이지 하단에 단순 ‘다음 글’이 아니라 **“이 프로젝트의 테스트 자동화 방식이 궁금하다면 → Study-06 검증 사례 보기”**처럼 질문형 추천 카드를 배치해 2페이지 이상 탐색 비율을 높입니다.

## 4. 4주 실행 계획 (Action Plan)

| 주차 | 실행 항목 | 완료 기준 (산출물) |
| --- | --- | --- |
| **1주차** | 기준선(Baseline) 계측 설정 및 첫 화면·상단 4줄 요약 카드 도입 | 최근 2주 또는 초기 테스트 그룹의 평균 체류 시간·스크롤 깊이 기록, 대표 프로젝트 3개 상단 요약 적용 |
| **2주차** | 대표 프로젝트 3개 케이스 스터디 개편 (문제·대안 비교·검증 결과 중심) | 프로젝트별 트레이드오프 표와 테스트 증거 섹션 반영 |
| **3주차** | 페이지 내 즉시 조작 가능한 경량 인라인 데모 1~2개 삽입 | 외부 페이지 이탈 없이 페이지 안에서 3회 이상 클릭·조작 가능한 데모 위젯 동작 확인 |
| **4주차** | 질문형 다음 프로젝트 추천 동선 연결 및 전후 지표 비교 검증 | 개편 전후 지표 비교표 작성, 역효과 발생 요소 제거 또는 유지 결정 |
