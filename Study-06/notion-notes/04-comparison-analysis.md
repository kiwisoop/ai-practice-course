# 일반 방식 vs Sequential Thinking MCP 비교 분석

- **작성일:** 2026-11-17 (한국 시간)
- **비교 대상:**
  1. 일반 방식: [`02-dwell-time-basic.md`](02-dwell-time-basic.md) (`체류 시간 늘리기`)
  2. Sequential Thinking MCP 실제 사용: [`03-dwell-time-sequential-thinking.md`](03-dwell-time-sequential-thinking.md) (`체류 시간 늘리기-체계적인 구상`)

## 1. 핵심 비교표 (실행 계획·측정 지표·근거)

| 비교 기준 | 일반 방식 (`체류 시간 늘리기`) | Sequential Thinking MCP (`체류 시간 늘리기-체계적인 구상`) | 차이의 실질적 의미 |
| --- | --- | --- | --- |
| **문제 정의 및 근거** | 방문자가 흥미를 느끼고 머물 만한 요소(스토리텔링, 데모, 가독성, 모바일 최적화)를 병렬적으로 나열함 | 체류 시간을 **조기 이탈률($r_{bounce}$)**과 **잔류 탐색 시간($T_{engaged}$)**의 결합으로 분해하고, 채용 담당자의 탐색 병목(긴 서론 기피)을 근거로 제시함 | 단순 아이디어 나열을 넘어 **왜 특정 조치가 체류 시간을 늘리는지 인과 관계**가 명확해짐 |
| **가설 점검·수정 여부** | 첫 응답에서 제시한 5가지 전략을 수정 없이 그대로 유지함 | Step 3(`isRevision: true`)에서 “화려한 애니메이션·영상 추가” 가설이 로딩 지연(LCP 악화)으로 이탈을 유발할 수 있음을 짚고 **API 키 없는 경량 인라인 데모**로 수정함 | 실제 적용 시 발생할 수 있는 **역효과(부작용)를 사전에 걸러냄** |
| **실행 계획의 구체성** | 즉시(1주) / 단기(2~3주) / 중기(1개월)의 3단계 우선순위 요약 | 1~4주차별로 **선행 계측(Baseline) → 케이스 스터디 개편 → 경량 데모 삽입 → 전후 비교 후 유지/폐기 결정**까지 완료 산출물을 명시함 | 실행 전 **기준선(Baseline) 확보**가 포함되어 실제로 2배가 되었는지 검증 가능함 |
| **측정 지표 (KPI)** | 평균 체류 시간, 이탈률, 페이지뷰/세션, 스크롤 깊이 4가지를 제시함 | 주 지표(평균 체류 시간 2.0배, 참여 세션 비율), 보조 지표(75% 스크롤, 데모 조작률 25%), **역효과 방지 가드레일 지표(LCP 2.5초 이내, GitHub/연락 전환율 유지)**로 구분함 | 길고 복잡한 페이지를 만들어 **체류 시간만 늘고 정작 채용·연락 전환이 떨어지는 지표 왜곡을 방지**함 |

## 2. 분량과 품질에 대한 판단 (주의사항)

- 교재 예시에서는 일반 추론과 순차적 추론의 줄 수(분량) 차이를 직관적인 비교 지표로 소개하지만, **문서 분량이 길다는 이유만으로 전략의 성능이 더 좋다고 단정할 수 없습니다.**
- 실제로 포트폴리오를 빠르게 검토해야 하는 사용자에게는 장황한 계획서보다 **일반 방식의 간결한 5대 체크리스트**가 초기 착수용으로 더 읽기 편할 수 있습니다.
- 반면 **Sequential Thinking MCP 방식의 실질적 장점**은 분량이 아니라 다음 세 가지에 있습니다.
  1. **가설 수정(`isRevision`):** “인터랙티브 요소를 많이 넣자”는 초기 생각이 로딩 속도 저하를 일으킬 수 있음을 스스로 반박하고 ‘경량 인라인 데모’로 범위를 좁힌 점.
  2. **기준선(Baseline) 선행 측정:** 개편 전에 현재 체류 시간을 먼저 기록하도록 1주차 계획에 포함해 ‘2배 달성’ 여부를 검증 가능하게 만든 점.
  3. **가드레일 지표(Guardrail Metrics) 도입:** 체류 시간 증가가 로딩 지연이나 연락 전환 감소로 이어지지 않는지 함께 감시하도록 설계한 점.
