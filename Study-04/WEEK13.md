이 실습의 실제 위임은 Codex의 역할별 서브에이전트로 수행한다. Claude용 정의 파일도 제공하지만 Claude의 `/agents` 화면에서 생성·실행한 기록은 아니다. 파일 충돌을 피하려고 리뷰 → 최적화 → UX 순서로 작업한다.

## 리뷰에서 확인한 문제

1. 레시피 API의 `choices` 항목이 `null` 또는 문자열이면 처리되지 않은 `AttributeError`가 발생한다. 사용자 오류 안내로 전환해야 한다.
2. 동일 사진도 Streamlit 재실행마다 다시 디코딩·변환한다. 현재 세션의 미리보기를 재사용해야 한다.
3. 재료 인식 버튼이 비활성화되어도 사진·키·모델·전송 동의 중 무엇이 필요한지 해당 화면에서 알기 어렵다.

## 백업과 데이터

수정 전 소스와 기존 SQLite를 `backup/before-week13-20261117.tar.gz`에 보관했다. 가상환경·캐시·API 비밀 설정은 제외했다. 백업에는 로컬 계정과 레시피 DB가 포함되므로 `backup/`은 Git에서 제외한다.

복원이 필요하면 실행 중인 앱을 종료하고 압축을 별도 폴더에 풀어 비교한 다음 필요한 파일을 복원한다. DB를 덮어쓰면 백업 이후 저장한 내용이 사라질 수 있다.

## 확인 범위

수정 전 기존 자동 테스트 11개 통과. 수정 후 `.venv/bin/python -m unittest discover -v`로 13개 테스트가 모두 통과했다(5.151초). 기존 회원가입·생성·저장·삭제·데이터 보존 검사에 사진 재사용/잘못된 사진 교체와 준비 항목 안내 검사를 추가했다. API 테스트에는 잘못된 choice 요소 3종을 추가했다.

`compileall` 문법 검사 통과, `pip check` 의존성 충돌 없음. 로컬 서버는 `http://127.0.0.1:8513`에서 실행했다. 테스트는 임시 DB와 모의 API 응답을 사용한다. 실제 브라우저 조작, 실제 키·사진을 외부로 전송하는 API 재검사와 Claude 실행은 수행하지 않았다. 따라서 교재의 실 API 재료 인식·레시피 생성 시연은 별도 확인이 남아 있다.
