# Kiwibird 제품 요구사항 문서(PRD)

## 1. 프로젝트 개요

- 과목: 인공지능활용실습
- 과제: 4주차 개인용 할 일 관리 애플리케이션
- 프로젝트 폴더: `Study-02`
- 앱 이름: **Kiwibird**
- 한글 설명: 개인용 할 일 관리 앱
- 한 줄 소개: **오늘 할 일을 가볍게 정리해요.**

Kiwibird는 해야 할 일을 카테고리별로 기록하고, 마감일과 중요도를 확인하며, 완료 상황을 한눈에 볼 수 있는 개인용 웹 애플리케이션이다. 별도의 설치나 로그인 없이 브라우저에서 바로 실행할 수 있도록 만든다.

## 2. 프로젝트 목표

1. 교재의 단계별 프롬프트 방식을 따라 기능을 다섯 단계로 나누어 구현한다.
2. 기본 할 일 관리 기능부터 저장과 백업 기능까지 순서대로 완성한다.
3. 각 단계가 끝날 때 직접 실행하고 결과를 확인한다.
4. AI가 작성한 결과를 그대로 사용하지 않고 테스트와 Git 기록을 남긴다.
5. 처음 사용하는 사람도 설명 없이 쉽게 사용할 수 있는 화면을 만든다.

## 3. 사용 대상

- 과제, 공부, 개발 일정을 함께 관리하고 싶은 학생
- 업무와 개인 일정을 간단히 기록하고 싶은 사용자
- 복잡한 회원가입이나 서버 없이 혼자 사용할 할 일 앱이 필요한 사용자

## 4. 개발 환경과 제약

- 순수 HTML, CSS, JavaScript만 사용한다.
- 별도의 프레임워크나 외부 라이브러리를 사용하지 않는다.
- 별도의 서버나 데이터베이스를 사용하지 않는다.
- `index.html`을 브라우저에서 열어 실행할 수 있어야 한다.
- 할 일과 설정은 브라우저 `localStorage`에 저장한다.
- Windows, macOS, Ubuntu의 최신 브라우저에서 사용할 수 있게 한다.

## 5. 디자인 방향

- 초록색과 크림색을 중심으로 한 친근한 키위새 테마
- 앱 제목 옆에 작은 초록색 새 아이콘 표시
- 둥근 카드와 부드러운 그림자를 사용한 편안한 화면
- 라이트 모드와 다크 모드 모두 충분한 명암 대비 유지
- 모바일과 데스크톱 화면에 맞게 크기가 자연스럽게 변하는 반응형 구성
- 진행률이 100%이면 `오늘 할 일을 모두 끝냈어요!` 메시지 표시

## 6. 할 일 데이터

각 할 일은 다음 정보를 가진다.

| 항목 | 내용 | 필수 여부 |
|---|---|---|
| 내용 | 사용자가 입력한 할 일 | 필수 |
| 카테고리 | 업무, 과제, 공부, 취미, 개발, 개인 | 필수 |
| 마감일 | `YYYY-MM-DD` 형식의 날짜 | 선택 |
| 중요도 | 낮음, 보통, 높음 | 필수, 기본값은 보통 |
| 완료 여부 | 진행 중 또는 완료 | 필수 |
| 생성 시각 | 할 일을 처음 추가한 시각 | 자동 |
| 수정 시각 | 마지막으로 수정한 시각 | 자동 |

마감일은 다음과 같이 표시한다.

- 마감일까지 남은 날짜: `D-3`
- 오늘 마감: `오늘`
- 기한이 지남: `기한 지남`
- 마감일 없음: 날짜 표시 생략
- 완료한 항목: 기한 초과 경고 제외

## 7. 기본 카테고리

| 카테고리 | 색상 방향 | 사용 예시 |
|---|---|---|
| 업무 | 남색 | 업무와 일정 |
| 과제 | 주황색 | 학교 제출 과제 |
| 공부 | 파란색 | 복습과 시험 준비 |
| 취미 | 분홍색 | 운동과 여가 활동 |
| 개발 | 초록색 | 코딩과 개인 프로젝트 |
| 개인 | 보라색 | 약속과 생활 일정 |

사용자가 카테고리를 새로 만드는 기능은 이번 과제 범위에서 제외한다.

## 8. 단계별 구현 계획

### Step 1. 기본 구조와 핵심 기능

구현할 내용:

- `index.html`, `styles.css`, `script.js` 생성
- 할 일 내용 입력
- 추가 버튼과 `Enter` 키로 할 일 추가
- 체크박스로 완료 상태 변경
- 할 일 한 개 삭제
- 빈 내용 입력 방지
- 기본 키위새 테마 적용

완료 확인:

- 할 일을 정상적으로 추가할 수 있다.
- 체크박스를 누르면 완료 상태가 바뀐다.
- 삭제 버튼을 누르면 선택한 항목만 삭제된다.
- 빈 내용은 목록에 추가되지 않는다.

### Step 2. 카테고리와 UI 개선

구현할 내용:

- 업무, 과제, 공부, 취미, 개발, 개인 카테고리
- 할 일 추가 시 카테고리 선택
- 전체 및 카테고리별 필터
- 카테고리마다 색상과 이름 표시
- 마감일과 중요도 입력
- `D-숫자`, `오늘`, `기한 지남` 표시
- 모바일 화면 개선

완료 확인:

- 선택한 카테고리, 마감일, 중요도가 정확히 표시된다.
- 카테고리 필터에 해당하는 할 일만 보인다.
- 완료한 항목에는 기한 초과 경고가 표시되지 않는다.

### Step 3. 진행률 대시보드와 수정 기능

구현할 내용:

- 오늘 해야 할 일 개수
- 남은 일, 완료한 일, 기한이 지난 일 개수
- 전체 진행률 막대
- 카테고리별 작은 진행률
- 수정 버튼으로 할 일 수정
- 할 일을 더블 클릭해도 수정 가능
- 수정 화면에 기존 값 표시

완료 확인:

- 완료 상태가 바뀌면 개수와 진행률이 바로 갱신된다.
- 수정 버튼과 더블 클릭이 같은 수정 기능을 연다.
- 수정한 내용, 카테고리, 마감일, 중요도가 저장된다.
- 할 일이 없을 때도 진행률 계산 오류가 발생하지 않는다.

### Step 4. 다크 모드와 편의 기능

구현할 내용:

- 라이트·다크 모드 전환
- 처음 실행할 때 운영체제의 테마 설정 사용
- 사용자가 선택한 테마 저장
- 검색창
- 상태 필터: 전체, 진행 중, 완료, 기한 지남
- 카테고리 필터
- 정렬: 마감일순, 중요도순, 최근 등록순
- 여러 필터 동시 적용
- 필터 초기화
- 완료한 항목 일괄 삭제
- 자주 사용하는 기능의 키보드 단축키

완료 확인:

- 다크 모드에서도 모든 글자와 버튼을 읽을 수 있다.
- 검색, 상태, 카테고리, 정렬을 함께 사용해도 결과가 정확하다.
- 완료 항목 일괄 삭제는 확인 후 완료된 항목만 삭제한다.
- 저장한 테마가 다음 실행에도 유지된다.

### Step 5. 저장, 백업과 최종 완성

구현할 내용:

- `localStorage` 자동 저장과 복원
- JSON 파일로 할 일 내보내기
- JSON 파일에서 할 일 가져오기
- 가져오기 전 파일 구조 검사
- 가져오기 전 현재 목록 교체 여부 확인
- 오늘의 격언을 준비된 문장 중 무작위로 표시
- 전체 기능 최종 점검
- README에 사용법과 개발 과정 기록

완료 확인:

- 브라우저를 닫았다 열어도 할 일이 남아 있다.
- 내보낸 JSON 파일에 현재 목록이 들어 있다.
- 정상 JSON 파일을 가져오면 목록이 복원된다.
- 잘못된 파일은 기존 목록을 바꾸지 않고 오류를 안내한다.
- 데스크톱과 모바일 크기에서 주요 기능을 사용할 수 있다.

## 9. 안전한 데이터 처리

- 할 일 내용의 앞뒤 공백을 제거하고 빈 문자열은 저장하지 않는다.
- 사용자 입력은 HTML 코드로 실행하지 않고 일반 글자로 표시한다.
- 한 항목 삭제와 완료 항목 일괄 삭제 전에 확인한다.
- JSON 가져오기는 필요한 항목과 값의 형식을 검사한 후 처리한다.
- 가져오기 검사에 실패하면 현재 할 일 목록을 그대로 유지한다.
- 정상 파일을 가져올 때도 현재 목록을 교체할지 먼저 확인한다.
- API 키, 비밀번호 또는 개인정보를 저장하거나 외부로 전송하지 않는다.

## 10. 접근성과 사용성

- 입력창과 버튼에 이해하기 쉬운 이름을 표시한다.
- 키보드만으로 입력, 추가, 수정, 완료 처리를 할 수 있게 한다.
- 현재 포커스 위치가 눈에 보이도록 표시한다.
- 색상만으로 카테고리, 중요도, 오류 상태를 구분하지 않는다.
- 상태 변경과 오류 메시지를 화면에서 확인할 수 있게 한다.
- 모바일에서도 버튼을 누르기 충분한 크기로 만든다.

## 11. 이번 과제에서 제외하는 기능

- 회원가입과 로그인
- 서버 또는 클라우드 동기화
- 여러 사용자의 공동 작업
- 푸시 알림
- 반복 일정
- 사용자가 직접 만드는 새 카테고리
- 외부 격언 API 호출

필요한 핵심 기능을 완성한 뒤에만 추가 기능을 검토한다.

## 12. 개발 과정 기록

과정 중심의 과제가 되도록 다음 기록을 남긴다.

- `PRD.md`: 무엇을 만들기로 했는지 기록
- `PROMPTS.md`: 단계별로 AI에게 요청한 내용 기록
- `AGENTS.md`: 프로젝트 구조와 AI 작업 규칙 기록
- `README.md`: 설치 없이 실행하는 방법, 기능, 테스트 결과와 느낀 점 기록
- Git 커밋: Step 1부터 Step 5까지 단계별 변경 기록

각 단계가 끝나면 다음 순서로 진행한다.

1. 단계별 프롬프트 기록
2. 기능 구현
3. 브라우저에서 직접 확인
4. 발견한 문제 수정
5. 확인 결과 기록
6. 단계별 Git 커밋

## 13. 최종 완료 기준

다음 조건을 모두 만족하면 과제를 완료한 것으로 본다.

- 교재의 5단계 기능이 모두 동작한다.
- 추가 기능인 마감일, 중요도, 검색, 복합 필터와 상세 대시보드가 동작한다.
- 새로고침과 브라우저 재실행 후에도 데이터가 유지된다.
- JSON 내보내기와 가져오기가 안전하게 동작한다.
- 삭제와 가져오기 같은 데이터 변경 작업에 확인 절차가 있다.
- 라이트 모드와 다크 모드에서 내용을 읽을 수 있다.
- 키보드와 모바일 화면에서도 주요 기능을 사용할 수 있다.
- README에 실행 방법과 AI 활용 과정이 정리되어 있다.
- 단계별 프롬프트와 Git 커밋으로 작업 과정을 확인할 수 있다.
